# 登錄預約週曆教練下拉預設本人 — 設計規格

- 日期：2026-07-04
- 狀態：業主已核可（「看是哪一位教練登入，預設就是他；即便同時是管理者，也以教練身份為主」）

## 目標

教練後台「登錄預約」頁籤的教練選擇器（管理者才有，現寫死預設 `'all'`＝全部教練）改為：**預設選登入者自己的教練身份**；仍可手動切到「全部教練」或其他教練。非管理者教練本來就只看自己，不受影響。

## 行為規則（純前端 `public/coach.js`）

- 新增模組變數 `myCoachId`：管理者開機的 `setupCoachPicker()` 取得 `/api/coach/me`（自己的教練檔案）時順手記下 `self?.id`；404（無教練檔案）→ null。
- `regViewCoachId` 初值由 `'all'` 改為 `null`（＝尚未初始化）；`renderRegister()` 內建好選項後做一次性初始化：
  - `myCoachId` 存在**且在選項清單內**（選項只列 `is_active` 教練）→ 預設 `String(myCoachId)`；
  - 否則（無教練檔案、或自己的教練檔案未啟用、或教練清單載入失敗）→ 維持 `'all'`。
  - 判斷「在選項內」用 DOM select 語意：`picker.value = String(myCoachId)` 後回讀是否設定成功。
- 初始化只做一次；之後管理者手動切換的值照舊保留整個 session（既有行為）。
- 所有既有 guard 對 `null` 安全（`regTargetBody` 的 `regViewCoachId && …`、URL 組裝在初始化之後執行）。

## 範圍外

- 標題旁共用教練下拉（PR #61）不動（它本來就預設自己）。
- 非管理者流程零改動；後端零改動。

## 驗證

`node --check` ＋ Playwright：管理者登入 → 登錄預約 → 下拉預設為自己（非「全部教練」）、行事曆只顯示自己的課；切「全部教練」照常全覽；0 console error。
