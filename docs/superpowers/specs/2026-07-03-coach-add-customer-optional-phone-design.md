# 登錄預約新增客人「電話改選填」 — 設計規格

- 日期：2026-07-03
- 狀態：業主已核可設計（補電話入口沿用後台會員管理；接受無電話客人無法自查我的課表）

## 目標

教練後台登錄預約的「就地新增客人」（PR #77）目前強制填電話。改為**電話選填**：沒有電話也能建立客人並完成登錄預約，電話之後再由管理者於後台會員管理補上。

## 行為規則

### 後端 `POST /api/coach/customers`（requireCoach）

- **有帶電話**（非空白字串）→ 行為完全不變：`findOrCreateUserByPhone`（格式驗證 `invalid_phone`、員工電話守門 `phone_unavailable` 409、封存客人自動還原、同電話回既有帳號）。
- **未帶電話**（缺欄位／null／空白字串）→ 新路徑 `createCustomerNoPhone({ name })`：直接 INSERT 一筆 `role='user'`、`phone=NULL` 的客人。姓名必填（`missing_name` 400）。
  - 不做 find/合併（無電話可比對）；登錄彈窗的搜尋本來就會先列出同名既有客人（查無才顯示新增表單），重複建立屬教練有意為之。
- 判斷式：`phone != null && String(phone).trim() !== ''` 才算有帶電話（維持「數字型別電話 → invalid_phone」的既有行為）。
- DB 層無需改動：`users.phone` 可 NULL，唯一索引為 `WHERE phone IS NOT NULL`，多個無電話客人不衝突。

### 前端 `public/coach.js` `renderRegmNewCustomer`

- 移除「請填電話」必填擋。
- 電話欄 placeholder 改為「電話（選填，可之後再補）」。
- 電話留空 → 請求 body 不帶 `phone`；成功後照舊接方案選擇步驟。
- 搜尋結果列與編輯預約彈窗已對 NULL 電話容錯（`u.phone || ''`、有才顯示），不動。

## 已知取捨（業主已確認接受）

1. 無電話客人**無法**從「我的課表」（姓名＋電話查詢）查自己的課表與方案，也連帶無法自助綁定 LINE；補上電話後即恢復。
2. 該客人若之後自己用電話在前台預約，會建立**另一個**新帳號（舊帳號無電話可比對）——建議一有電話就到後台會員管理補上。

## 不做（YAGNI）

- 教練端補電話入口（業主選沿用後台會員管理；該處已有格式驗證＋撞號 409）。
- 我的課表／LINE 綁定查詢邏輯改動。
- 無電話帳號與有電話帳號的合併工具。

## 測試

擴充 `tests/coach-add-customer-api.test.js`（既有 API 測試檔）：

1. 無電話建立 → 200、回 `phone: null`、DB `phone IS NULL`、role=user。
2. 空白字串電話 → 視為未帶、建立成功。
3. 兩個無電話客人可並存（不同 id，不合併）。
4. 無電話且缺名 → 400 `missing_name`。
5. 既有五個案例（有電話建立／缺名／壞電話／員工電話 409／既有電話 find 不重複）不變、必須續過。
